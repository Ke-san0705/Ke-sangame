# グラフィック制作基準（DEV-03a）

[Issue #97](https://github.com/Ke-san0705/Ke-sangame/issues/97) に示された「計算無双 ラウンド6開発仕様書」§5 の素材規格を、制作・描画で使える形にまとめる。登録と既存素材の評価は[素材台帳](asset-register.md)を参照。

## キャラクター

| 種別 | 制作寸法（原寸） | 体型 |
| --- | --- | --- |
| 主人公 | 128 × 128 px 基本枠 | 5〜6頭身 |
| 小型敵 | 32〜64 px | |
| 通常敵 | 64〜128 px | |
| 大型敵 | 128〜256 px | |

- 透過 PNG のスプライトシートで納品する。各シート内のセルは同一寸法とし、セル間の隙間や外枠を設けず、余白が必要な場合は透過ピクセルをセル内に置く。
- 右向きを原画の基準とする。左向きの描画が必要な場合は、配置アンカーを中心に反転する。
- 足元中央を基準に配置アンカーを設定する。各クリップで同じ基準点が維持されるように原画をそろえ、動作中の浮き沈みや踏み込みは絵の中で表現する。
- 拡大にはニアレストネイバーを使う。DOM では `image-rendering: pixelated`、Canvas 2D では `imageSmoothingEnabled = false` を使用する。
- 各フレームの外見、武器、姿勢の連続性を確認する。初期制作の動作別フレーム数の目安は [DEV-03b](https://github.com/Ke-san0705/Ke-sangame/issues/101) を参照。

## 背景

- 2D ドット絵、640 × 360 px を基準とする。
- 遠景・中景・地面を個別のレイヤーとして納品し、遠景から地面の順で重ねる。各レイヤーは共通の画面原点（左上）に合わせ、下のレイヤーを見せる箇所は透過にする。
- 問題文と入力 UI の視認性を優先し、彩度とコントラストを抑える。

## アニメーション JSON

[サンプル JSON](../src/lib/fixtures/sprite-animation.example.json) は形式を確認するためのデータ。サンプルに対応する実画像は不要。納品時は JSON と対応する PNG を同じディレクトリに置く。

| 項目 | 意味 |
| --- | --- |
| `image` | シートのファイル名。英小文字または数字で始まり、以降は英小文字・数字・ハイフン・アンダースコアを使用し、拡張子を `.png` とする |
| `cell.width` / `cell.height` | セルの幅と高さ。正の整数 px |
| `grid.columns` / `grid.rows` | シートの列数と行数。正の整数。シート寸法はセル寸法と各軸のセル数の積 |
| `animations` | 動作名をキーにしたオブジェクト。1 件以上 |
| `startFrame` / `endFrame` | 開始と終了を含む 0 始まりの整数。左上から右へ進み、行末で次の行に移る。最後の番号は `columns * rows - 1` |
| `fps` | 1 秒当たりのフレーム数。有限の正数 |
| `anchor.x` / `anchor.y` | 各セルの左上から右・下への足元中央のオフセット。整数 px。各軸の範囲は 0 からセル寸法まで（右端・下端を含む） |

描画コードでは JSON を Vite の `?raw` で読み込み、`loadSpriteAnimation` に渡す。配布ファイルを取得する場合も、HTTP の成功を確認してからレスポンス本文を同じ関数に渡せる。

```ts
import json from './character.json?raw'
import { loadSpriteAnimation } from '../lib/spriteAnimation'

const definition = loadSpriteAnimation(json)
const idle = definition.animations.idle
```

JSON の構文、必須項目、セル内のアンカー範囲、シート内のフレーム範囲を検証する。不正な定義は項目名付きのエラーになり、部分的な定義は返さない。プレビューなどで読み込みを回復できる場合は、呼び出し元でエラーを捕捉して既存の静止画へ戻せる。PNG の実寸、透過、向き、足元に対するアンカーの位置は納品時に確認する。
